# EvoWiki 管理中心重构规格

## Problem Statement

当前工作台管理仅提供创建成员、创建项目和授予单一项目权限的三张表单。系统管理员无法浏览、搜索、编辑、停用或追溯成员与项目；项目只是文件夹而不是被治理的对象；权限变更没有可查询记录。这个界面和底层模型无法承担企业文档访问边界的日常维护。

本重构在继续其余 MVP Tickets 前，建立完整但克制的成员、项目、直接授权和审计治理能力。它保持 EvoWiki 的单实例、单一 SQLite 文件、Git 文档资产与运行数据分离、服务唯一推送者及路径沙箱边界。

## Solution

系统管理员从工作台右上角的设置入口打开宽管理抽屉。抽屉内使用 Tabs 提供成员、项目和审计日志三张紧凑表格；创建和编辑操作在二级抽屉中完成。成员、项目、直接授权和审计记录存入 `evowiki.db`；项目文档与依赖配置继续留在受保护的 Git 文档仓库。

成员使用本地账号登录。系统管理员可创建、编辑姓名、重置密码、启用或停用成员以及管理系统管理员身份。项目成为有负责人和状态的一等实体。成员只通过直接项目角色获得权限。所有管理变更生成仅系统管理员可查询的脱敏审计日志。

## User Stories

1. 作为系统管理员，我希望从工作台右上角进入管理中心，以便不离开日常工作区即可维护治理数据。
2. 作为系统管理员，我希望在成员 Tab 查看全部成员及其登录名、姓名、文字头像、系统身份和启用状态，以便了解谁可以访问系统。
3. 作为系统管理员，我希望按登录名、姓名、系统身份和状态筛选成员，以便快速找到目标成员。
4. 作为系统管理员，我希望创建具有唯一登录名、姓名和临时密码的成员，以便为团队开通本地访问。
5. 作为新成员，我希望首次使用临时密码登录后必须设置自己的密码，以便管理员不长期掌握我的登录凭据。
6. 作为系统管理员，我希望修改成员姓名，以便成员列表和文字头像反映正确的展示信息。
7. 作为系统管理员，我希望重置成员密码，以便成员遗失凭据后能重新进入系统。
8. 作为系统管理员，我希望停用成员，以便其立即失去所有已有会话和后续登录权限，而历史评论与审计记录仍可追溯。
9. 作为系统管理员，我希望重新启用成员，以便保留其历史身份并恢复后续登录能力。
10. 作为系统管理员，我希望管理系统管理员身份，以便将全局治理职责交接给合适成员。
11. 作为系统管理员，我希望系统阻止我停用或降级最后一个启用的系统管理员，以便实例始终可治理。
12. 作为系统管理员，我希望查看全部项目的标识、名称、负责人和状态，以便维护企业文档空间。
13. 作为系统管理员，我希望创建项目并指定负责人，以便每个文档空间在创建时就有清晰责任人。
14. 作为项目负责人，我希望自动成为该项目的项目管理员，以便立即维护该项目的资料和成员。
15. 作为系统管理员或项目管理员，我希望编辑活动项目的名称、描述和负责人，以便项目资料保持准确。
16. 作为系统管理员，我希望归档项目并在需要时恢复，以便停止写入旧项目而不丢失文档、授权和历史记录。
17. 作为已授权成员，我希望归档项目继续只读可见，以便查阅历史知识而不会继续修改它。
18. 作为系统管理员或项目管理员，我希望在项目详情中添加、改角色和撤销直接成员授权，以便维护最小权限。
19. 作为系统管理员，我希望在成员详情中查看并维护其所有项目授权，以便处理人员加入、转岗和离开。
20. 作为查看者，我希望只能读取已发布文档，以便不会意外修改项目资产。
21. 作为编辑者，我希望在活动项目中创建、修订、提交草稿和发布文档，以便维护知识资产。
22. 作为项目管理员，我希望在活动项目中维护成员授权、负责人和项目资料，以便项目日常治理无需依赖系统管理员。
23. 作为系统管理员，我希望查询成员、项目和授权变更的审计日志，以便在访问边界变化后追溯操作者和结果。
24. 作为系统管理员，我希望审计日志不包含密码、密码哈希或文档正文，以便审计不成为新的敏感数据泄露面。
25. 作为系统管理员，我希望成员、项目和授权界面使用明确的成功与失败反馈，以便修正冲突、无效状态或无权限操作。
26. 作为运维人员，我希望现有文档访问、MCP 草稿和发布接口继续在后端执行项目 ACL 与路径沙箱校验，以便管理界面的变化不会削弱既有安全边界。

## Implementation Decisions

- 管理中心只向系统管理员显示和开放。设置按钮打开宽抽屉，抽屉内使用成员、项目和审计日志 Tabs。成员与项目的创建、编辑、密码重置、状态变化和授权编辑均使用二级抽屉；不保留一次性手工表单区。
- 成员是本地认证主体，具有不可变且唯一的登录名、可修改姓名、密码哈希、启用状态、系统角色、会话版本、首次修改密码标记及必要时间戳。文字头像从姓名生成，不保存或上传头像文件。
- 系统角色只有普通成员和系统管理员。项目角色只有 `viewer`、`editor` 和 `project_admin`。系统管理员是全局身份，不是项目 ACL 的一种角色。
- 成员停用和密码重置必须增加会话版本或采用等价机制。每个受保护请求都验证成员启用状态及当前会话版本，使已签发 JWT 立即失效。首次登录和管理员重置后的临时密码只能进入修改密码流程。
- 系统必须始终存在至少一名启用的系统管理员。禁止对最后一名启用系统管理员执行停用或降级操作。
- 项目是 SQLite 中的一等实体，具有不可变、安全的项目标识、名称、描述、负责人、状态和时间戳。项目标识继续映射到受保护的物理项目目录，所有文件访问仍通过 `os.path.commonpath` 校验。
- 项目管理资料以 SQLite 为唯一事实来源。Git 侧 `meta.json` 仅保留 `dependencies`，不重复保存名称、描述、负责人或状态。
- 项目负责人必须是成员，并自动拥有该项目的 `project_admin` 角色。负责人可转移；在转移负责人或归档前，负责人不得被降级、停用或撤销项目管理员权限。
- 项目只支持活动和归档两种状态。归档项目仍对已有授权成员只读可见，不允许文档写入、成员授权变更或项目资料修改；仅系统管理员可以创建、归档、恢复项目。
- 项目权限是成员到项目的直接、唯一授权关系，不引入部门、用户组、继承授权或角色组合。成员与项目两侧都能维护同一授权关系。
- 审计日志是 SQLite 中不可变的追加记录，至少包含操作者、动作、对象类型和标识、脱敏前后摘要、时间及关联项目（如适用）。仅系统管理员可以查询；当前无期限保留。密码、密码哈希、文档正文、JWT 和其他秘密不得进入日志。
- 管理 API 采用资源化契约：成员提供列表、创建、详情、姓名更新、状态更新、系统角色更新和密码重置；项目提供列表、创建、详情、资料更新、负责人转移、归档和恢复；项目授权提供列表、授予或更新及撤销；审计日志提供只读的筛选和服务端分页；认证提供当前身份和强制修改密码接口。
- 成员和项目列表在当前约 50 名活跃成员的单实例规模下使用搜索与状态筛选，不做分页。审计日志因持续增长必须使用服务端分页和筛选。
- 首个正式版本发布前不构建数据库迁移框架，也不保留开发数据库中的历史业务数据。允许重建 `evowiki.db` 后以新模型初始化；首次发布后的兼容策略另行决策。
- 前端隐藏的操作不是授权边界。所有角色、归档状态、负责人约束、会话失效和审计写入都必须由后端统一强制执行。

## Testing Decisions

- 完整 FastAPI HTTP 边界是管理治理的主要测试 seam。测试使用临时 SQLite 和真实应用实例，通过认证、管理、项目访问和文档接口验证可观察行为，而不绑定私有函数调用。
- 延续现有认证和项目 API 的测试风格。成员测试覆盖创建、唯一登录名、姓名更新、临时密码首次修改、重置密码后的旧会话失效、停用后的旧会话失效、重新启用和最后一个系统管理员保护。
- 项目测试覆盖创建、负责人的自动项目管理员授权、资料更新、负责人转移、归档、恢复、归档项目只读和项目目录的路径沙箱保持有效。
- 授权测试覆盖三种项目角色的 API 行为、系统管理员的全局权限、项目管理员的项目范围、直接授权的授予/更新/撤销，以及成员和项目两侧显示一致。
- 审计测试覆盖每个管理变更产生一条不可变记录、仅系统管理员可查询、筛选分页稳定，以及记录不泄露密码、哈希、JWT 或文档正文。
- 前端测试覆盖系统管理员可打开管理 Tabs、表格筛选、二级抽屉提交与错误反馈、非系统管理员不可见管理入口、归档项目的只读状态和文字头像展示。测试通过接口模拟验证用户可见行为，不断言组件内部状态。

## Out of Scope

- 部门、用户组、嵌套角色、继承授权和批量导入成员。
- 邮件邀请、邮件通知、外部 SSO、密码策略、密码找回或图片头像上传。
- 首次正式版本发布前的数据库迁移框架、历史权限导入和旧数据库数据保留。
- 项目物理删除、成员物理删除、审计日志删除、审计日志自动清理和可配置留存策略。
- 由项目管理员创建、归档或恢复项目。
- 文档评论、Office/PDF 转换、附件、WebSocket、版本时光机、LLM Wiki 和其余未完成的 MVP/路线图能力。

## Further Notes

- 本规格优先于旧 MVP 规格中“管理功能只有创建与授予”的最小表述；其余 Markdown 草稿、发布、Git、RAG、MCP 与路径安全约束不变。
- 管理治理重构完成并通过 HTTP 边界测试后，才恢复执行其余 MVP Tickets。
- 当前审计无期限保留是本期选择。清理、归档、备份与恢复策略进入 V2 后再根据实际数据量和合规要求单独决策。
